# FHIR Patient Record Explorer

A command-line tool that parses FHIR R4 patient bundles (the JSON format used for exchanging healthcare records) and turns each resource type into a tidy pandas table.

Built as a data engineering take-home assessment (2022).

## What it does

1. Looks up a patient's bundle in `data/` by first and last name.
2. Parses the bundle with the `fhir.resources` models, so each record is validated against the FHIR schema instead of being read as raw JSON.
3. Prints the patient's demographics (ID, name, date of birth, gender).
4. Offers a menu for viewing any of the patient's records as a table:

| Option | Resource | Columns |
|---|---|---|
| 1 | Conditions | condition, onset date |
| 2 | Observations | observation, value, unit, date |
| 3 | Medications | medication, date prescribed |
| 4 | Procedures | procedure, date |
| 5 | Encounters | type, location, provider, date |
| 6 | Claims | provider, insurer, date, type, item, cost (USD) |
| 7 | Immunizations | vaccine, date |

Every table carries the patient's UID, so the output can be joined or loaded into a database later.

## Running it

```bash
pip install pandas numpy tqdm fhir.resources
python main.py
```

Put the FHIR bundle files (one JSON file per patient) in a `data/` folder next to `main.py`. The assessment supplied synthetic patients generated by [Synthea](https://synthetichealth.github.io/synthea/), with file names like `Aaron697_Dickens475_<uuid>.json`. Enter the name parts exactly as they appear in the file name, for example `Aaron697` and `Dickens475`.

## Tech

Python, pandas, `fhir.resources` (Pydantic models for FHIR R4)
